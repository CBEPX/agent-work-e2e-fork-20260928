# Разработка

## Требования

- **Podman** (все Go-команды выполняются в контейнерах — локальный Go не нужен)
- **make** (GNU Make)
- **tsh** (Teleport CLI, для `make deploy`)

## Структура проекта

```
cmd/serial-proxy/       Точка входа главного бинарника
internal/serial/        Серийное соединение и пул (Conn, Pool)
internal/history/       SQLite история команд (DB)
deployments/systemd/    Systemd unit-файл
docs/en/                Документация на английском
docs/ru/                Документация на русском
```

## Сборка

```bash
make build       # Статический бинарник через Podman
make all         # Сборка + тесты + линтер
```

## Тесты

```bash
make test        # go test -race -count=1 ./...
```

## Линтер

```bash
make lint        # golangci-lint с 50+ линтерами
```

Конфигурация `.golangci.yml` обеспечивает строгое качество кода:
- Аудит безопасности (`gosec` в режиме аудита)
- Обнаружение теней (`govet` shadow analyzer)
- Обертка ошибок (`wrapcheck`, `errorlint`, `err113`)
- Ограничения сложности (циклическая ≤15, когнитивная ≤15, функция ≤80 строк)
- Производительность (`prealloc`, `perfsprint`, `intrange`)
- Современные паттерны Go (`modernize`, `exptostd`)

## Развертывание

```bash
make deploy      # Сборка + SCP на pve-netlab + перезапуск systemd
```

## Соглашения по коду

- **Пакеты**: `internal/` для приватной реализации, без `pkg/` (нет публичного API)
- **Ошибки**: всегда оборачивать с контекстом (`fmt.Errorf("connect vmid %d: %w", vmid, err)`)
- **Логирование**: только `log/slog`, JSON handler, структурированные пары ключ-значение
- **Конкурентность**: мьютекс на каждое серийное соединение, мьютекс пула для доступа к карте
- **Именование**: строчные неэкспортируемые типы в internal пакетах, MCP типы с префиксом `mcp`

## Добавление нового MCP инструмента

1. Определить структуры ввода/вывода с тегами `jsonschema` в `cmd/serial-proxy/main.go`
2. Написать функцию-обработчик
3. Зарегистрировать через `mcp.AddTool()`
4. Добавить соответствующий REST эндпоинт при необходимости
5. Обновить документацию и CHANGELOG
